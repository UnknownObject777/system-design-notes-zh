# 网络爬虫

**一句话概括：** 按规则发现网页、抓取内容，并避免重复或过度访问同一网站。

## 业务问题

搜索或数据分析系统需要从大量网页收集信息，但 URL 数量巨大、网页会变化，站点也有访问规则。

## 为什么需要它

队列和调度让抓取任务可并行、可重试；去重能省带宽和存储，域名级调度可避免压垮单个站点。

## 为什么不用更简单的方案

单线程按链接递归能做小规模抓取，但会卡在慢站点、重复访问和深度优先陷阱。简单增加爬虫进程会造成重复抓取和突发请求。

## 它怎么工作

从种子 URL 开始，规范化并去重后进入待抓队列；按域名限速取任务、下载页面、解析新链接，再把内容交给索引或存储管道。

## 会怎么坏

重定向、无限日历链接、动态页面、恶意文件和站点封禁都会影响抓取。必须尊重站点策略、访问频率和隐私要求，并防止 SSRF 等安全问题。

## 我怎么验证它

在本地小网站上构造循环链接、重复 URL、慢响应和 429 返回，观察去重、重试、域名限速和队列恢复。

## 记住这几件事

- URL 队列和去重是基本骨架。
- 调度要按站点控制速率。
- 抓取规模越大，安全和礼貌越重要。
