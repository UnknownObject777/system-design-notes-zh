# 第 9 章：设计网络爬虫

## 引言
**网络爬虫（web crawler）**，也称为蜘蛛（spider）或机器人（robot），用于发现和收集网页、图片、视频等网络内容。本章重点介绍如何为**搜索引擎索引**设计可扩展的网络爬虫。

### 网络爬虫的应用
1. **搜索引擎索引：** 收集网页以创建可搜索的索引（例如 Googlebot）。
2. **网页归档：** 保存网络数据以供将来使用（例如美国国会图书馆）。
3. **网络挖掘：** 从网络数据中提取知识（例如对股东报告的金融分析）。
4. **网络监测：** 检测版权或商标侵权行为。

### 设计挑战
一个好的网络爬虫必须解决：
- **可扩展性（Scalability）：** 通过并行化处理数十亿个页面。
- **健壮性（Robustness）：** 处理损坏的 HTML、崩溃以及恶意链接。
- **礼貌性（Politeness）：** 避免向服务器发送过多请求，以免造成过载。
- **易扩展性（Extensibility）：** 以最小的改动支持新的内容类型。

---

## 步骤 1：理解问题

### 需求
1. 每月爬取 **10 亿个网页**（400 页/秒，峰值 800 QPS）。
2. 仅收集 **HTML 内容**。
3. 跟踪新增和更新的页面。
4. 忽略重复内容。
5. 将抓取的数据存储 **5 年**，大约需要 30 PB 的存储空间。

## 步骤 2：高层设计

### 组件

1. **种子 URL（Seed URLs）：** 爬虫的起始点。
    - 需要精心选择作为良好的起点，使爬虫能够利用它遍历尽可能多的链接。
    - 可以基于流行网站的地区分布，也可以基于主题。
    - 策略：按地区或主题分类（例如体育、医疗保健）。

2. **URL 队列（URL Frontier）：** 存储待下载的 URL。
   - 以 **FIFO 队列** 实现。

3. **HTML 下载器：** 从 URL 队列提供的 URL 下载网页。

4. **DNS 解析器：** 将 URL 转换为 IP 地址。

5. **内容解析器：** 验证并解析网页。
   - 丢弃格式不正确的页面。

6. **内容去重（Content Seen?）：** 使用哈希比较检查重复内容（比较两个网页的哈希值）。

7. **内容存储：** 将 HTML 页面存储在磁盘上（热门内容存储在内存中以减少延迟）。

8. **URL 提取器：** 从解析后的页面中提取新链接。

9. **URL 过滤器：** 排除列入黑名单或错误的 URL。

10. **URL 去重（URL Seen?）：** 跟踪已访问的 URL 以避免重复。

11. **URL 存储：** 存储已访问过的 URL。


---

### 工作流程
1. 将**种子 URL** 添加到 URL 队列中。
2. **HTML 下载器**获取 URL，并通过 DNS 解析器解析其 IP。
3. **内容解析器**验证内容并将其传递给“内容去重”组件。
4. 如果内容是新内容，则通过 **URL 提取器** 提取链接。
5. 过滤并将唯一链接添加到 URL 队列中。

## 步骤 3：关键组件深入剖析
### DFS/BFS
- 网络可以被视为一个有向图，网页是节点，超链接（URL）是边。
- 图遍历通常使用 BFS（广度优先搜索），因为深度可能非常深，因此 DFS（深度优先搜索）并不理想。
- 标准 BFS 没有考虑 URL 的优先级，并非每个页面都具有相同的质量和重要性。


### URL 队列
- **礼貌性：** 
    - 确保同一时刻每个主机只发送一个请求。在两个下载任务之间添加延迟。
    - 使用从主机名到队列和工作线程（下载线程）的映射。
    - 每个下载线程都有自己独立的 FIFO 队列，并且只从该队列下载 URL。

        <img src="./images/politeness.png" alt="礼貌性" width="500">

    - **队列路由器（Queue router）：** 确保每个队列（b1、b2、… bn）只包含来自同一主机的 URL。
    - **映射表（Mapping table）：** 将每个主机映射到一个队列。
    - **队列选择器（Queue selector）：** 每个工作线程被映射到一个 FIFO 队列，并且只从该队列下载 URL。队列选择逻辑由队列选择器完成。
    - **工作线程 1 到 N：** 工作线程从同一主机顺序下载网页。可以在两个下载任务之间添加延迟。

- **优先级：** 
    - 为重要页面分配更高的优先级（例如，根据 PageRank 或更新频率）。

        <img src="./images/prioritizer.png" alt="优先级" width="500">
    
    - **优先级排序器（Prioritizer）：** 以 URL 为输入，计算优先级。
    - **队列 f1 到 fn：** 每个队列都有指定的优先级。高优先级队列被选中的概率更高。
    - **队列选择器：** 随机选择一个队列，但偏向优先级较高的队列。
    - **前端队列（Front queues）：** 负责管理优先级排序。
    - **后端队列（Back queues）：** 负责管理礼貌性。

- **新鲜度（Freshness）：** 根据更新历史或重要性进行重新爬取。


### HTML 下载器
- **robots.txt 合规：** 遵守 robots.txt 文件中的规则。
- **性能优化：**
  1. 使用多台服务器进行分布式爬取。
  2. 使用 **DNS 缓存** 以避免重复查询。
  3. 在地理上分布爬取服务器，以加快下载速度。
  4. 使用较短的超时时间，以避免慢速或无响应的服务器。

### 健壮性
1. **一致性哈希（Consistent Hashing）：** 在服务器之间有效地分配负载。
2. **错误处理：** 防止异常导致系统崩溃。
3. **数据校验：** 确保内容完整性。

### 易扩展性（Extensibility）
- 为新的内容类型添加模块（例如 PNG 下载器、网页监测器）。
- 示例：接入一个用于监测网页内容的模块，以检测版权侵权行为。

### 避免有问题的内容
1. **重复内容：** 使用哈希比较检测。
2. **蜘蛛陷阱（Spider Traps）：** 使用 URL 长度限制等技术避免无限循环。
3. **数据噪音：** 过滤广告或垃圾信息等无关内容。

## 步骤 4：总结
### 关键要点
1. 网络爬虫必须在可扩展性（Scalability）、健壮性（Robustness）、礼貌性（Politeness）和易扩展性（Extensibility）之间取得平衡。
2. **礼貌性** 可防止服务器过载，而 **优先级** 可确保重要页面优先被爬取。
3. 高效的存储和错误处理对于处理大规模爬取至关重要。

### 其他考虑因素
- **服务端渲染（Server-Side Rendering）：** 处理由 JavaScript 或 AJAX 生成的动态内容。
- **反垃圾措施（Anti-Spam Measures）：** 排除低质量或无关的页面。
- **数据库分片（Database Sharding）：** 使用复制和分片扩展数据层。
- **水平扩展（Horizontal Scaling）：** 使用无状态服务器高效地扩展爬取作业。
- **分析（Analytics）：** 收集并分析数据以获得洞察。
