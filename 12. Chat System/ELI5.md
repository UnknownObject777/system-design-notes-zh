# 聊天系统

**一句话概括：** 让消息从发送者到达正确会话，并在断线后仍能补齐。

## 业务问题

用户需要实时收发消息，但设备可能离线、网络会断，消息还要按会话保存和同步。

## 为什么需要它

持久化消息、连接管理和离线投递分开后，系统能处理实时连接与可靠存储两类不同工作。

## 为什么不用更简单的方案

普通 HTTP 请求适合偶尔拉取，不适合高频实时双向消息；长连接降低交互延迟，但占用连接资源，需要心跳、重连和扩展策略。

## 它怎么工作

客户端建立长连接并鉴权；发送消息时先写入持久化层，再通过在线连接投递；接收端确认或稍后按会话游标补拉。多设备状态需按设备或用户定义。

## 会怎么坏

服务切换时可能重复投递；离线队列可能无限增长；在线状态可能短暂不准。传输“恰好一次”通常不能简单保证，业务应使用消息 ID 做去重。

## 我怎么验证它

发送消息时断网、重连、切换设备并重复提交，检查消息顺序、去重、离线补拉和已读状态。

## 记住这几件事

- 实时连接与消息持久化是两件事。
- 断线恢复靠游标、补拉和去重。
- 先定义会话顺序与多设备语义。
