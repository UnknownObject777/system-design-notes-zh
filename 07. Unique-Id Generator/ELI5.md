# 分布式唯一 ID 生成器

**一句话概括：** 多台机器并发创建记录时，为每条记录分配不冲突、可接受的 ID。

## 业务问题

多个服务节点同时插入订单或消息，不能依赖单机自增值来保证全局唯一。

## 为什么需要它

唯一 ID 便于存储、查找和关联记录；是否要有序、可读、短小或隐藏业务量，也会影响设计。

## 为什么不用更简单的方案

集中式票据服务容易理解，但吞吐和可用性受单点协调限制；UUID 分布式生成方便，却较长且通常不按时间顺序排列。Snowflake 类方案用时间、节点号和序列号组合，但依赖时钟与节点号管理。

## 它怎么工作

明确位数布局和唯一性范围；每个节点取得不重复的节点标识，在时间窗口内递增序列。时钟回拨、序列耗尽或节点标识冲突时，必须定义阻塞、拒绝或切换策略。

## 会怎么坏

时钟倒退可能造成重复；机器误用同一节点号会直接冲突；把 ID 当秘密令牌也不安全。唯一不代表不可猜、连续或严格有序。

## 我怎么验证它

多进程并发生成大量 ID，检测重复、顺序和分布；模拟时钟回拨、重启和节点号重复，确认系统按预期失败。

## 记住这几件事

- 先定义唯一性和排序要求。
- 每种方案都把复杂度放在不同地方。
- ID 设计要明确时钟和节点故障策略。
